# 面板服接入指南

> 「面板服」指 Minecraft 服务端跑在托管面板里的情况：MCSManager、翼龙 / Pterodactyl、
> 宝塔的进程守护管理器，或者简幻欢 / 雨云这类租用面板。
>
> 这类机器通常不给你 SSH，所以「在 MC 机器上装个 Agent」这条路走不通。
> 不装 Agent 能做到哪一步、怎么配、哪里会卡住，下面分开说。

---

## 一、三档方案，能做的事差很多

| | 方案 A：只接面板 API | 方案 B：面板 API + RCON | 方案 C：面板 API + Agent |
|---|---|---|---|
| 要在 MC 机器上装东西 | 不用 | 不用（改 server.properties） | 要装一个 php 脚本 |
| 适合 | 租用服、只有 Web 控制台的面板 | 绝大多数面板服的最优解 | 自己有机器、能 SSH |
| 读服务端日志做诊断 | ✅ | ✅ | ✅ |
| 玩家视角连通性探测 | ✅ | ✅ | ✅ |
| 自动加白名单 / 解封 / 踢人 | ✅（MCSManager、翼龙用面板控制台） | ✅（走 RCON，有回显更可靠） | ✅ |
| 自动重启服务端 | ✅（面板开关机） | ✅ | ✅ |
| 看 TPS / 在线人数 / 封禁列表 | ❌ | ✅ | ✅ |
| 进程、磁盘、CPU 采集 | 翼龙可以，其它不行 | ❌ | ✅ |
| 备份存档 / 从服务端取回 MOD | ❌ | ❌ | ✅ |
| 宝塔面板能做游戏指令吗 | 不能（宝塔没有控制台接口） | ✅ | ✅ |

三档怎么选：

- 能改 `server.properties` 就开 RCON（方案 B），这一步性价比最高。
- 租用服改不了/端口不通的，方案 A 也够用一大半，白名单和解封照样能自动修。
- 面板里能开 RCON 的宝塔服必须开，否则白名单这类修复一条都下不去。

---

## 二、方案 A：只接面板 API

### 2.1 后台里的通用步骤（四个面板都一样）

1. 登录后台 → 左侧「服务器与 Agent」
2. 找到你的服务器，点右上角「配置」展开表单
3. 「执行器」选 `none（只诊断）`
   > 面板服没有 Agent，别选 agent，否则检查项会一直显示"无法采集"。
4. 往下滚到「面板 API」区域，填：

   | 字段 | 填什么 |
   |---|---|
   | 面板类型 | 见下面各面板的小节 |
   | 面板地址 | 面板的访问地址 |
   | API 密钥 | 面板里生成的密钥 |
   | 接口超时（秒） | 保持 12 就行 |
   | 跳过 HTTPS 证书校验 | 只在面板用自签证书、不勾就连不上时才勾 |

5. 勾上「启用面板 API」
6. 保存 → 回到服务器卡片，右上角会出现「测试面板 API」按钮，点它

这一步必须先过。它会告诉你连没连上、认出了哪些能力。失败时会把实际请求的 URL 和
面板的原始响应贴出来，填错 ID 时这是最快的定位方式。

命令行也可以：

```bash
php bin/mcfix.php panel              # 列出所有配了面板的服务器
php bin/mcfix.php panel survival     # 体检某一台：连通性 → 能力 → 读日志试一次
```

### 2.2 MCSManager

填这些：

| 后台字段 | 填什么 |
|---|---|
| 面板类型 | `MCSManager` |
| 面板地址 | 例如 `http://127.0.0.1:23333` 或 `https://panel.example.com` |
| API 密钥 | 面板右上角用户信息里生成的 API 密钥（管理员账号的密钥就是管理员权限） |
| 远程服务 UUID | 节点 UUID，官方文档里叫 `daemonId` |
| 实例 UUID | 你这个 MC 实例的 UUID，官方文档里叫 `uuid` |
| 面板内的服务端目录 | 实例的文件管理根目录，例如 `/opt/mc/survival` |

两个 UUID 怎么找：打开这个实例的控制台页面，看浏览器地址栏，里面会出现两个 UUID。
和「远程服务 / 节点」列表里那条记录一致的是节点 UUID，另一个就是实例 UUID。

拿不准的时候有两条硬办法：

1. 浏览器按 F12 → Network，在面板里点一下控制台输入框发一条指令，看面板自己发的请求里
   `uuid` 和 `daemonId` 分别是什么。这个做法跨版本都可靠。
2. 先随便填，点「测试面板 API」，失败时会把面板的原始响应贴出来，
   通常直接说缺哪个参数或哪个 UUID 不存在。

关于面板版本：MCSManager 这几年的版本把接口路径和参数名改过几轮
（`remote_uuid` → `daemonId`、指令从 POST body 改成放查询串、读文件从
`/api/files/download` 改成 `PUT /api/files/`）。适配器两种写法都会试，
所以新旧版本都能用；判断依据是面板返回的 `status` 字段。
如果两个版本都不是，用下面 2.6 的办法覆盖路径。

配完之后能做：读日志、下发游戏指令（白名单/解封/踢人/保存世界/重载插件）、开关机、列目录、读文件。

做不到：进程列表、磁盘余量、TPS、CPU/内存（MCSManager 的 API 不暴露这些给外部调用）。

### 2.3 翼龙 / Pterodactyl（含 Pelican）

填这些：

| 字段 | 值 |
|---|---|
| 面板类型 | `翼龙 / Pterodactyl（含 Pelican）` |
| 面板地址 | 例如 `https://panel.example.com` |
| API 密钥 | `ptlc_...`（子用户密钥）或 `ptla_...`（管理员密钥） |
| 密钥模式 | 见下面 |
| 服务器短 ID | 面板地址栏 `/server/xxxxxxxx` 里的那一段 |
| 面板内的服务端目录 | 翼龙一般是 `/home/container` |

两种密钥怎么选：

| | `ptlc_`（Client，推荐） | `ptla_`（Application） |
|---|---|---|
| 权限范围 | 只有这一个服务器 | 面板管理员级别 |
| 泄露风险 | 小 | 大 |
| 能力 | 发指令、开关机、读日志、列目录、读资源 | 同上 |

优先用 `ptlc_`。在面板【账号 → API Credentials】里创建，权限只勾这一个服务器。

关于日志路径：翼龙的文件接口是相对服务端根目录的，所以「日志路径」填 `logs/latest.log`
就对，不要写 `/home/container/logs/latest.log`。这一点和宝塔不一样，宝塔要写完整绝对路径。

配完之后能做：读日志、发游戏指令、开关机、列目录、读 CPU/内存/磁盘占用（翼龙独有）。
有了资源读数，系统还能识别出"进程在跑但端口连不上"这种情况，不会误判成服务端挂了。

### 2.4 宝塔面板

填这些：

| 字段 | 值 |
|---|---|
| 面板类型 | `宝塔面板（MC 跑在本机）` |
| 面板地址 | 例如 `https://127.0.0.1:8888` |
| API 密钥 | 宝塔【设置 → API 接口】里的密钥 |
| 进程 ID | 进程守护管理器里那个 MC 项目的 ID |
| 面板内的服务端目录 | 例如 `/www/minecraft/survival` |
| 跳过 HTTPS 证书校验 | 宝塔默认自签证书，这里通常要勾 |

宝塔没有"发游戏指令"的接口，所以：

- 它能做：读日志、列目录、读文件、进程启停
- 它不能做：白名单、解封、踢人，这些必须走 RCON

也就是说，宝塔服的正确姿势是「宝塔面板 API + RCON」：
面板负责读日志和启停进程，RCON 负责发游戏指令。见下一节。

### 2.5 租用服 / 自研面板（自定义 HTTP 接口）

简幻欢、雨云这类面板，或者你自己写的转发脚本，用「自定义 HTTP 接口」适配器。

在「面板 API」区域展开「自定义接口参数」，用占位符描述怎么发请求：

| 字段 | 例子 |
|---|---|
| 指令接口 URL | `http://127.0.0.1:8080/api/console` |
| 开关机 URL | `http://127.0.0.1:8080/api/power` |
| 日志接口 URL | `http://127.0.0.1:8080/api/log?tail=2000` |
| 列目录 URL | `http://127.0.0.1:8080/api/files` |
| 请求方法 | `POST` |
| 请求体模板 | `{"cmd":"{command}"}` |
| 开关机请求体 | `{"action":"{action}"}` |
| 回显字段路径 | `data.output` |
| 自定义请求头 | 每行一条 `Key: Value`，或一整段 JSON |

可用占位符：`{command}`（游戏指令）、`{action}`（start/stop/restart/kill）、`{path}`（文件路径）。

只填得出来的那几个就行。只填指令接口，就只有"发指令"能力；只填日志接口，就只能诊断。

> ⚠️ 这个适配器发出去的永远只是游戏指令和开关机信号，
> 不会把玩家输入拼进 shell，也不支持任意文件写入。这是设计边界，不是没实现。

### 2.6 接口路径对不上

面板版本一多，内置的接口路径难免有对不上的。这时候不用改代码：

1. 浏览器打开你的面板，按 F12 → Network，勾上 `Fetch/XHR` 过滤
2. 在面板里做一次你想让 MCFix 做的动作（比如在控制台发一条 `list`）
3. 看那条请求的 URL、方法、请求体长什么样
4. 回到 MCFix 后台，在「面板 API」区域展开「接口路径覆盖」，
   每行填一条 `名称=路径`，保存

可用的名称（想覆盖哪个就填哪个，留空 = 用内置默认值）：

| 名称 | 默认路径 | 用途 |
|---|---|---|
| `command` | `/api/protected_instance/command` | 下发游戏指令（新版） |
| `command_legacy` | `/api/instance/command` | 下发游戏指令（旧版回退） |
| `power_open` / `power_stop` / `power_restart` / `power_kill` | `/api/protected_instance/open` 等 | 开关机（新版） |
| `power` | `/api/instance` | 开关机（旧版回退） |
| `outputlog` | `/api/protected_instance/outputlog` | 读实例控制台输出（读日志主线） |
| `read_file` | `/api/files/` | 读文件内容 |
| `list_dir` | `/api/files/list` | 列目录 |
| `download` | `/api/files/download` | 旧版下载 |
| `server` | `/api/client/servers/<id>` | 翼龙：连通性测试 |
| `resources` | `/api/client/servers/<id>/resources` | 翼龙：资源占用 |

改完点「测试面板 API」验证。还不通就用 `php bin/mcfix.php panel <server_id>` 看实际发出了什么。

## 三、方案 B：面板 API + RCON（推荐）

RCON 是 Minecraft 服务端自己的远程控制台，和面板无关：只要你能改 `server.properties` 就能开。

### 3.1 在面板里改 server.properties

用面板的文件管理器打开服务端根目录下的 `server.properties`，加上/改成：

```properties
enable-rcon=true
rcon.port=25575
rcon.password=换成一段够长的随机密码
```

然后在面板里重启一次服务端（改这个必须重启才生效）。

### 3.2 在 MCFix 后台填 RCON

回到「服务器与 Agent → 配置」，在「RCON」区域：

| 字段 | 填什么 |
|---|---|
| 启用 RCON | 勾上 |
| RCON 地址 | 见下面 |
| RCON 端口 | `25575`（和你上面填的一致） |
| RCON 密码 | 和 `server.properties` 里完全一致，不能有前后空格 |

RCON 地址填什么，取决于 MCFix 装在哪：

| 情况 | 填什么 |
|---|---|
| MCFix 和 MC 在同一台机器（宝塔常见） | `127.0.0.1` |
| MCFix 在另一台机器，面板给你的是独立 IP | 面板给你的那个 MC 服务器 IP |
| 面板把 MC 关在容器里、只对外映射了游戏端口 | 多半填不通，见下面的坑 |

填好保存，然后在服务器卡片上点「测试面板 API」旁边的诊断，或者直接命令行：

```bash
php bin/mcfix.php diagnose survival Steve cannot_join
```

输出里会有一条 `[✓] whitelist` / `[✗] whitelist`，能直接看出 RCON 通没通。

### 3.3 开了 RCON 之后多了什么

- 诊断：TPS、在线人数、白名单开关、玩家是否在白名单、是否被封禁/禁言
- 修复：白名单、解封、解禁言、踢人、清背包、保存世界、重载插件，而且有回显，
  执行结果是不是真的成功，系统能直接看到，比面板控制台可靠

## 四、方案 C：面板 API + Agent（能力最全）

如果你的面板能给你一个 shell（翼龙的 Startup 里能改启动命令、宝塔能开终端、
或者你本来就有 SSH），那么在 MC 机器上跑一个 Agent 能补齐剩下所有能力：

- 进程、磁盘、CPU 采集
- 备份存档（`tar` 打包 world 目录）
- 从服务端 `mods/` 目录取回 MOD 文件发给玩家
- 按 systemd / screen / tmux / 自定义命令重启

这时「执行器」改成 `agent`，面板 API 可以同时保留。
系统按能力自动选路：读日志优先走面板，发游戏指令优先走 RCON，重启用 Agent。

具体部署步骤看后台的「接入与排查」页，或者 `README.md` 的第 5 步。

## 五、各方案能力总表（按代码里的实际行为）

| 检查项 / 修复动作 | 只有面板 API | 面板 API + RCON | + Agent |
|---|---|---|---|
| 玩家视角连通性（MC 协议握手） | ✅ | ✅ | ✅ |
| 服务端日志分析 | ✅ 需 `read_log` | ✅ | ✅ |
| 插件报错归集 | ✅ 需 `read_log` | ✅ | ✅ |
| 进程 CPU / 内存 | 翼龙 ✅ / 其它 ❌ | 同左 | ✅ |
| 端口监听、进程存在、磁盘余量 | ❌ | ❌ | ✅ |
| TPS、在线人数 | ❌ | ✅ | ✅ |
| 白名单 / 封禁 / 禁言 | ❌ | ✅ | ✅ |
| 加白名单 / 解封 / 解禁言 / 踢人 / 清背包 | MCSManager、翼龙 ✅ / 宝塔 ❌ | ✅ | ✅ |
| 保存世界 / 重载插件 | MCSManager、翼龙（无回显） | ✅ 有回显 | ✅ |
| 重启服务端 | 有 `power` 能力就 ✅ | ✅ | ✅ 最可控 |
| 备份存档 / 取回 MOD / 只读体检 | ❌ | ❌ | ✅ |

> 「只有面板 API」时，做不到的检查项不会假装通过：
> 界面上显示 `[?] 无法在 MC 机器上采集该项数据：该服务器未配置执行器（只在面板侧诊断）`，
> 而 RCON 类会显示 `[-] 未开启 RCON，无法用控制台指令验证`。这两句是正常的，不是配置错了。

## 六、排查手册

先用这两条命令，90% 的问题能自己定位：

```bash
php bin/mcfix.php panel <server_id>       # 面板 API：连通性、能力、实际请求与响应
php bin/mcfix.php diagnose <server_id> <玩家名> cannot_join   # 完整诊断一遍
```

| 现象 | 原因与处理 |
|---|---|
| 点「测试面板 API」报 `Failed to connect` | MCFix 所在机器连不到面板地址。面板地址填错、端口没放行，或者面板只监听内网 |
| 报 `401` / `403` / `apikey 无效` | 密钥填错或权限不够。翼龙要确认密钥模式（`ptlc_` 选 client、`ptla_` 选 application）选对了 |
| 报 `404` | 面板版本和适配器的接口路径不一致 → 用「自定义接口参数」里的字段覆盖路径 |
| 报证书错误 | 面板用了自签证书。能换成受信任证书就换；实在不行才勾「跳过 HTTPS 证书校验」 |
| 报 `MCSManager 指令下发失败` | 多半是实例 UUID 或远程服务 UUID 填错，报错里会带上面板的原始响应 |
| 提示「未配置远程服务 UUID，无法通过面板读取文件」 | MCSManager 读日志需要 `daemon_id`，去面板的「远程服务」列表里取 |
| 日志读到了但内容是空的 | 「日志路径」不对。宝塔要绝对路径、翼龙和 MCSManager 要相对服务端目录的路径 |
| 界面上全是 `[?] 无法在 MC 机器上采集` | 正常，面板 API 拿不到进程/磁盘这类机器侧数据。想要就上 Agent |
| 一直是「未开启 RCON，无法用控制台指令验证」 | 正常，要么去开 RCON，要么接受这几项验不了 |
| 一直判「服务端当前处于离线状态」，但面板显示在运行 | 见下面的坑 1 |
| 白名单自动修复显示"已投递"但没有回显 | 正常，面板控制台接口不回显。想看结果就开 RCON，或者去面板控制台翻一下 |

## 七、面板服特有的坑

### 坑 1：把「地址填错」误判成「服务端挂了」

系统判断"服务端在不在"的方式，是从 MCFix 这台机器发一次 Minecraft 协议握手，
等价于玩家点"加入服务器"。所以：

- 你填的 `host:port` 必须是从 MCFix 机器能连上的地址
- 玩家通过 SRV 记录域名连接的场景，要填真实的 host:port。
  本系统不做 SRV 查询，`_minecraft._tcp` 那条记录它不会去看
- 填了面板节点内网地址、或者只对游戏流量放行的端口，握手都会失败

系统会自己分辨：如果面板能提供进程读数（翼龙的资源接口）
或 Agent 报告进程在跑，它会改判成

> 结论：本机连不上 MC 端口，但服务端看起来仍在运行
> 问题码：`mc_unreachable` 严重级别：high

并且不会去重启一台好机器。看到这条就去查地址/防火墙/SRV。

只有确实没有任何反证时才会判 `server_offline`。

### 坑 2：面板服通常开不了 RCON 的对外端口

RCON 是服务端自己监听的 TCP 端口。面板服常见两种情况：

- 端口只绑在容器/节点内部，MCFix 从外网连不上，只能靠面板控制台发指令
- 面板允许你在防火墙里放行，那就放行 MCFix 那台机器的 IP，别忘了顺便限制来源

MCSManager 和翼龙都有控制台接口，所以"没有 RCON"并不等于"不能自动修白名单"。
宝塔是例外：它没有控制台接口，不开 RCON 就一条游戏指令都发不出去。

### 坑 3：面板密钥的权限比你想的大

- MCSManager 的 API 密钥基本等于面板管理员
- 翼龙的 `ptla_` 是面板管理员级别的，`ptlc_` 只对单个服务器有效
- 宝塔的 API 密钥能让持有者读服务器上的文件

所以：**能用 `ptlc_` 就别用 `ptla_`**；面板地址尽量走 HTTPS；
非自签证书不要勾「跳过证书校验」，勾了之后密钥和日志内容在网络上就是明文可改的。

### 坑 4：面板控制台没有回显，"已投递"不等于"执行成功"

MCSManager 和翼龙的控制台接口都是投递即返回，拿不到指令的输出。
所以系统只能说"已投递到控制台"。想要确凿的成功/失败判断，就开 RCON。

这也是为什么「诊断 → 修复 → 复验」这条链路重要：修完系统会再连一次看问题还在不在，
而不是听面板说"收到了"就当成功。

**有没有例外**：有。少数自建/转发接口是真的会回显的。这种情况走「自定义 HTTP 接口」，
并且**必须填上 `output_path`**（告诉系统回显在响应 JSON 的哪个字段里）：

```php
'panel' => [
    'type'        => 'custom',
    'api_url'     => 'http://127.0.0.1:8080/api/console',
    'body'        => '{"cmd":"{command}"}',
    'output_path' => 'data.output',   // ← 填了这一项，才允许把它用于需要解析输出的检查
],
```

填了它，这台服的检查（`list` / `tps` / `whitelist list` / `banlist`）就能在没有 RCON 时
走面板控制台 —— 诊断里那几项不用再因为"没开 RCON"而跳过。

不填就仍按"不回显"处理。这是个刻意的取舍：系统宁可报"这项验证跳过"，
也不愿意把 `{"message":"success"}` 里的 `success` 当成回显去解析 ——
那样得出的"白名单是空的""玩家不在线"看起来有结论，其实是猜的。

> 所以看到诊断里某项显示"未开启 RCON，这项验证跳过"，先确认两件事：
> 这台服的面板接口**到底回不回显**，以及 `output_path` 有没有填对。
> 用 `php bin/mcfix.php panel <server_id>` 能直接看到实际请求与响应。

## 八、三档方案各管一段

> 面板 API 负责"看得见"，RCON 负责"下得去手"，Agent 负责"够得着机器"。
>
> 面板服的现实是：前两样基本都能拿到，第三样通常拿不到，而前两样已经能覆盖
> 「玩家进不去 → 自动加白名单/解封/重启 → 复验 → 通知你」这条主链路了。
