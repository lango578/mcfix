## 可信度标注

每一行都标了来源，按来源决定信不信：

| 标记 | 含义 |
|---|---|
| ✅ 实测 | 有人真的配通并跑过 |
| 📄 第三方文档 | 来自第三方集成文档，不是我或用户实测的，请自己确认一眼 |
| ❓ 待查证 | 还没查，别照着猜 |

主机商换面板、关 API 页面都是常事。写错的教程比没有教程更糟：用户会以为是自己填错了，来回折腾半天。所以没查的一律标「待查证」。

## 已查证的主机商

### 简幻欢（SimpFun / SFE4）

国内免费公益平台，自研面板，没有开放 API。和下面两家完全不是一类。

| 项 | 值 | 来源 |
|---|---|---|
| 面板 | 自研 SFE4（Docker 容器 + `start.sh` + 差异更新） | 📄 官方文档 |
| MCFix 面板类型 | ❌ 没有适配器，也不可能有：它没有开放 API 密钥页 | 📄 |
| 执行器能选什么 | `none`（推荐）或 `rcon`；不能选 `agent`，除非镜像里有 PHP | 📄 / ❓ |
| RCON | ⚠️ 能开，但要先新建实例端口（一次性收积分，且官方称「仅对必要稳定用户提供增加端口功能」） | 📄 |
| SSH | ❌ 不提供 | 📄 |
| SFTP | ✅ 有（实例 → 管理 → SFTP 文件管理服务器） | 📄 |
| 面板终端 | ✅ 有；把 `start.sh` 改成 `bash` 可拿到交互式 shell | 📄 |
| 详细教程 | [简幻欢接入指南](简幻欢接入指南.md) | 📄 已写（含 5 条待用户确认项） |

简幻欢用户注意两件事：

1. 连续 7 天不开启实例会被自动销毁（生成 60 日备份）。这会表现为 `server_offline`，别去重启一个已经不存在的实例。
2. 官方明说晚高峰关闭实例后可能无法再启动，所以重启类自动修复要在后台关掉。

它也不能用来建站（服务条款明确禁止，也禁止 FRP 等代理类应用），所以 MCFix 站点本身得放在别处，比如[宝塔](宝塔部署指南.md)。

| 面板 | ⚠️ 有两种，需自己确认，见下方说明 | — |
| MCFix 面板类型 | 若 Pterodactyl 系 → `翼龙 / Pterodactyl（含 Pelican）`；若 Multicraft → 选 `Multicraft` | — |

关于 BisectHosting 的面板，两份资料对不上：

| 来源 | 说的是 |
|---|---|
| 第三方集成文档（DeployHQ） | Starbase 面板基于 Pterodactyl |

## Pterodactyl 系主机商：通用接入步骤

BisectHosting / PebbleHost / Sparked Host / GGServers 四家都是 Pterodactyl 系，流程完全一样。下面是精简版，完整版（含每步的界面说明、排查表）见 [BisectHosting 接入指南](BisectHosting接入指南.md)。

第 1 步 · 拿服务器短 ID。看面板地址栏：`https://<面板域名>/server/3f2a1b9c` → `3f2a1b9c` 就是。

第 2 步 · 建 API 密钥。打开 `https://<面板域名>/account/api` → Create API Key → 权限全勾（只影响你自己这一台服务器）→ 复制那串 `ptlc_` 开头的密钥（只显示一次）。

> 打不开这个页面 = 主机商把 API 关了 → 只能走 RCON。见[面板服接入指南 · 方案 B](面板服接入指南.md)。

第 3 步 · 填进 MCFix 后台。后台 → 服务器与 Agent → 编辑服务器 → 面板 API：

| 界面字段 | 填什么 |
|---|---|
| 类型 | `翼龙 / Pterodactyl（含 Pelican）` |
| 密钥模式（翼龙） | `client（ptlc_，权限小）` |
| 面板地址 | `https://<面板域名>`（不带斜杠、不带 `/server/xxx`） |
| API 密钥 | 第 2 步复制的 `ptlc_...` |
| 服务器短 ID（翼龙） | 第 1 步拿到的那段 |
| 面板内的服务端目录 | `/home/container` |

第 4 步 · 执行器选 `none`。这是最容易错的一步，界面上的选项是 `none（面板服选这个：用面板 API 修）`。

这一项填错不会报错。选 `agent` 的话任务会一直卡在"排队中"，界面看起来正常，玩家只会觉得"说修了没反应"。原因见[第 1 节](BisectHosting接入指南.md#1-最容易踩的坑executor-一定要填-none)。

第 5 步 · 点「测试面板 API」。看到 `power` 就说明自动重启可用。

第 6 步 · 建议再配 RCON。面板 API 万一挂了，RCON 还能兜底。见[面板服接入指南 · 方案 B](面板服接入指南.md)。

### Multicraft 适配器已实现（1.11.0）

Apex Hosting 用的 Multicraft 现在可以直接接了，不用再退回 RCON。

| 界面字段 | 填什么 |
|---|---|
| 类型 | `Multicraft（Apex Hosting 等，也见于部分 BisectHosting）` |
| 面板地址 | `https://<面板域名>/api.php`，必须带 `/api.php`；只填域名会收到一段 HTML 而不是 JSON |
| 用户名 | 你登录 Multicraft 面板的用户名。Multicraft 是唯一需要用户名 + 密钥两个凭据的面板，因为签名要用到它 |
| API 密钥 | 面板里生成的 API 密钥 |
| 服务器 ID | Multicraft 的数字服务器 ID（不是 UUID） |
| 面板内的服务端目录 | 填了也不起作用，见下面的能力边界 |

能力边界：

| 能力 | 支持 |
|---|---|
| 下发游戏指令（白名单 / 解封 / 踢人 / 保存 / 重载） | ✅ |
| 开关机、自动重启 | ✅ |
| 读服务端日志 | ✅ |
| CPU / 内存 / 玩家数 | ✅ |
| 列 mods 目录 / 读文件 | ❌ Multicraft 的 API 没有文件接口 |
| 取回 MOD 给玩家下载 | ❌ 同上 |

Multicraft 用户拿到的是完整的修复闭环（该修的都修得了），但少了 MOD 相关功能。适配器不会假装支持这些，后台点「测试面板 API」时会把边界一并告诉你。

> BisectHosting 同时有 Multicraft 和 Pterodactyl 两种面板。打开 `https://<你的面板域名>/api.php`，有 API 响应 = Multicraft；404 = Pterodactyl 系。两种现在都支持了。

### 协议实现的一个坑（写给以后维护的人）

Multicraft 的认证不是把密钥原样发过去，而是算签名：

```
message = 把每个参数的「键名 + 值」依次拼接（键名也要拼，无分隔符）
签名     = hash_hmac('sha256', message, api_key)
```

网上流传的一份 2013 年单文件客户端用的是 `md5(key + method + user + 只有值)`，那是错的或已过期（少了键名，且摘要算法不同）。照那份写会一直认证失败，而面板只回一句含糊的错误。

正确实现见 `src/Panel/MulticraftPanel.php`，并有测试钉住这个规格。

## 你自己怎么判断（三分钟）

不用等教程。打开你的面板，按顺序看：

第 1 步 · 看地址栏。

```
https://<面板域名>/server/3f2a1b9c
                        ^^^^^^^^
```

有 `/server/<一段短ID>` 这种形状，十有八九是 Pterodactyl 系。MCFix 里直接选 `翼龙 / Pterodactyl（含 Pelican）`，那个短 ID 就是「服务器短 ID」。

第 2 步 · 试 `/account/api`。浏览器打开 `https://<面板域名>/account/api`。

- 能打开、能看到 "Create API Key" → 走面板 API 路线，能力最全（含自动重启）
- 404 或没这个页面 → 主机商把它关了，走 RCON 路线（[面板服接入指南 · 方案 B](面板服接入指南.md)）

第 3 步 · 找 RCON。在面板里找 `server.properties` 的编辑入口（通常在"配置文件"或"启动参数"里），看能不能改：

```properties
enable-rcon=true
rcon.port=25575
rcon.password=你自己设一串随机的
```

能改 → RCON 可用（记得改完重启服务器）。面板不让你改这几行 → 只能靠面板 API 那条路。

第 4 步 · 看有没有 SSH。面板里找 "SSH" 或 "Console/Terminal" 之类。只有 SFTP 没有 SSH 是常态，那就意味着 Agent 路线用不了，执行器要选 `none`。

## 四条路线在不同主机商上的可用性

不管哪家主机商，MCFix 就这四条路。对照着看你有什么：

| 路线 | 前提 | 商业主机商上通常 |
|---|---|---|
| 面板 API | 主机商开放 API 密钥页 | 看运气。Pterodactyl 系的往往开着 |
| RCON | 能改 `server.properties` | 多数能 |
| Agent | 能在 MC 机器上跑常驻进程 | ❌ 基本不可能：不给 SSH，也没法常驻 |
| SSH | 主机商给 SSH | ❌ 绝大多数不给 |

商业面板服基本就是「面板 API + RCON」二选一或都配。两条都配是最优：RCON 有回显、最快；面板 API 负责 RCON 干不了的，特别是服务器挂了要重启。
