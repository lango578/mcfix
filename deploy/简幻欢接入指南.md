# 简幻欢（SimpFun / SFE4）接入指南

> 简幻欢没有开放面板 API，MCFix 的「面板 API」那条路走不通。
> 能走的是 RCON（有三个前置条件，见第四节）和只做客户端分析（零成本，一定能用）。
>
> 通用原理见 [面板服接入指南](面板服接入指南.md)；这份只讲简幻欢特有的事实和步骤。

---

## 零、先看这张表

| 路线 | 简幻欢能不能用 | 卡在哪 |
|---|---|---|
| 面板 API | ❌ 不行 | SFE4 是简幻欢自研面板，没有 `/account/api` 这种开放密钥页面 |
| RCON | ⚠️ 可以，但要先过三关 | ① 得能新建实例端口 ② 得知道新端口映射到容器哪个端口 ③ 端口必须是裸 TCP 转发 |
| Agent | ❓ 取决于镜像里有没有 PHP | 机制上可行（能改 `start.sh`、能拿 shell、有 SFTP），但官方镜像只声明了 JDK / Python |
| SSH | ❌ 不提供 | 但有 SFTP + 面板终端，够做手工操作 |
| 只做客户端分析（执行器 `none`） | ✅ 一定能用 | 零成本、不碰服务器，见第三节 |

先做第三节（立刻有用），再考虑第四节的 RCON。

## 二、先搞清楚简幻欢是什么（它和商业面板服不一样）

简幻欢是免费公益平台（官方自称"前身铁锈联机4，9年运营经验"，运营方为沈阳简幻网络科技有限公司），
所以它的机制和"花钱买的商业服"差别很大，不了解这些会直接导致 MCFix 误报。

### 2.1 SFE4 = 镜像 + `start.sh` + 差异更新 📄

官方原话：

> SFE4 预设只是能够为你提供一个 `环境（镜像）` + `启动命令（start.sh）` + `差异更新`

也就是说你的实例跑在一个 Docker 容器里，启动靠根目录下的 `start.sh`（一个 bash 脚本）。
官方明确提示：「由于 Docker 镜像的特性，可能导致部分启动参数无法在简幻欢使用」。

`start.sh` 是可以编辑的，这一点后面 Agent 方案要靠它。

### 2.2 实例会被自动销毁 📄

这是最容易被误判的一条。官方机制：

| 机制 | 内容 |
|---|---|
| 计费 | 实例一天内处于开启状态就扣一天积分，每天 `00:00:00–23:59:59` 为一个计费周期 |
| 积分不足 | 自动停止 |
| 连续 7 天不开启 | 自动销毁实例，并生成一个有效期 60 日的备份 |
| 签到 | 每次签到 +50 积分；积分超过 400 时无法继续签到 |
| 磁盘超额 | 超出套餐额度部分收 1 积分/GB/天 |

> ⚠️ 对 MCFix 的影响：实例被销毁后，你填的 `host:port` 会连不上，
> MCFix 会判成 `server_offline`（严重级别 high）并可能触发重启类动作，而重启一个不存在的实例是没用的。
> 看到这类告警，先去简幻欢控制台的「记录」页看看是不是实例已经没了。

### 2.3 晚高峰可能关了起不来 📄

> 晚高峰时使用人数较多，简幻欢为拒绝超开，在节点负载较高情况下，可能导致关闭实例后无法再启动，
> 请谨慎在晚高峰时段进行重启，关闭操作。

> ⚠️ 对 MCFix 的影响：自动修复里有一条是「重启服务器」。
> 在简幻欢上这条要慎重：重启等于"关闭再启动"，而官方直接说了晚高峰关了就未必起得来。
> 建议把「重启类配方」在后台逐个关掉（后台可以按服务器禁用某个修复动作），只留白名单/解封/保存这类不改进程状态的。

### 2.4 服务条款禁止的行为 📄

> 简幻欢为尽可能保证提供正常的服务，禁止了一些行为，如使用简幻欢建站等。
>
> 于实例端口处：我们不支持搭建代理类应用，包括但不限于 FRP，一经发现，将会按照服务条款处理！

> ✅ MCFix 的 Agent 是主动外连的（面板把任务放队列里，Agent 自己来取，
> 不需要开放任何入站端口），所以它不构成"建站"，也不需要 FRP。
> 但这是我读代码 + 官方条款得出的判断，不是官方认可。自己掂量，别把实例当服务器用。

### 2.5 其他会影响排查的机制

| 机制 | 说明 | 对 MCFix 的影响 |
|---|---|---|
| 节点负载 | 节点无资源时禁止创建/变配；节点故障也靠变配恢复 | 实例可能因为平台侧原因起不来 |
| 任务队列 | 创建、解压、变配都是"排队执行" | 你在面板里点了解压，不等于立刻完成 |
| 账号不允许异 IP 登录 | 会遇到「您的 IP 并未在白名单中」 | 跟 MCFix 无关，但排查时容易懵 |
| 反小号机制 | 开小号 / 重复注销注册会触发 | — |

## 三、方案 A：零成本，先把这个做起来

这条路不需要简幻欢给你任何权限，也不需要开端口。

MCFix 对「纯客户端报错」的分析完全不依赖服务器连接。模组冲突、缺前置、
Java 版本不对、内存不足、Mixin 失败这类问题，系统只读玩家上传的崩溃报告就能给结论。

### 3.1 怎么配

后台 → 服务器与 Agent → 新增/编辑服务器：

| 界面字段 | 填什么 |
|---|---|
| 服务器名 | 随便，比如 `简幻欢主服` |
| 地址 / 端口 | 见下面 3.2，填了才能做"服务端在不在"的探测 |
| 执行器 | `none（面板服选这个：用面板 API 修）` |
| RCON | 不启用 |
| 面板 API | 不填 |

> ⚠️ 执行器一定选 `none`。这一项填错不会报错：选 `agent` 的话任务会一直卡在"排队中"，
> 界面看起来正常，玩家只会觉得"说修了没反应"。原因见
> [面板服接入指南 · 坑](面板服接入指南.md#坑-1把地址填错误判成服务端挂了)。

### 3.2 地址填什么 📄

官方给的自定义地址机制：

> 您可以使用其它地址：`你的自定义后缀.9666.fun:你的实例端口` 连接服务器，
> 其中自定义后缀可任意填写，也可不填，如：`myserver.9666.fun:25565`。
>
> 如你希望使用你的域名访问简幻欢的实例，可通过 CNAME 解析 `play.simpfun.cn` 实现。

所以 MCFix 里：

| 字段 | 填什么 |
|---|---|
| 地址 | `play.simpfun.cn`（或者你喜欢的 `随便什么.9666.fun`，官方说后缀可任意填） |
| 端口 | 面板「实例」页显示的那个实例端口号，不是你 `server.properties` 里的 `server-port` |

> ❓ 待查证：端口被解析成"任意后缀都能连"，说明路由是按端口号认实例的。
> 那"实例端口"到底是平台分配给你的对外端口，还是你容器内的端口？
> 以你面板上实际显示的数字为准，别照抄 `25565`。

### 3.3 这一档能得到什么 / 得不到什么

| 能力 | 方案 A |
|---|---|
| 玩家提交反馈、看进度 | ✅ |
| 客户端崩溃报告分析（模组冲突 / 前置缺失 / Java 版本 / 内存） | ✅ 完整 |
| 和服务端 MOD 清单比对 | ❌ 读不到服务端文件 |
| "服务端在不在"的握手探测 | ✅（填了地址就行） |
| 自动加白名单 / 解封 / 保存世界 / 重载 | ❌ 一条都发不出去 |
| 自动重启 | ❌ |

对很多玩家来说这一档就够了：80% 的"进不去"其实是客户端问题。

## 四、方案 B：RCON（要过三关）

RCON 是 Minecraft 服务端自己的远程控制台，和面板无关：只要你能改 `server.properties` 就能开。
简幻欢能改（有文件管理 + SFTP），但端口是个坎。

### 4.0 先过这三关，过不了就别折腾了

| 关卡 | 怎么判断 | 过不了怎么办 |
|---|---|---|
| ① 你能不能新建实例端口？ | 实例 → 管理 → 「实例端口」→ 看有没有"新建" | 官方说「为避免滥用，仅对必要稳定用户提供增加端口功能」，新号可能压根没这个按钮。过不了就退回方案 A |
| ② 新端口映射到容器哪个端口？ | 新建端口时看它让你填什么 | ❓ 待查证，见 4.3 |
| ③ 是不是裸 TCP 转发？ | 见 4.5 的验证方法 | 如果是 HTTP 反代，RCON 用不了 |

> 成本：新建端口一次性收一定数量积分，且每个实例有端口上限 📄。
> 按官方 50 积分/天、签到 50 积分/天来算，一个端口大概等于一天到几天的签到。

### 4.1 改 `server.properties`

进实例 → 点「文件」→ 找到根目录的 `server.properties` → 编辑，加上/改成：

```properties
enable-rcon=true
rcon.port=25575
rcon.password=换成一段够长的随机密码
```

改完重启一次服务端（这个必须重启才生效）。

> 也可以用 SFTP（实例 → 管理 → 「SFTP 文件管理服务器」）拉下来改完再传上去。
> 如果走 SFTP，传完必须去「工具箱 → 解决权限和文件名乱码问题」点一次执行 📄，
> 否则会因权限不足导致服务器运行异常。这是官方明确警告的。

### 4.2 新建一个端口给 25575

实例 → 管理 → 「实例端口」→ 新建 → 记下平台给你的那个对外端口号。

官方原话：「您可在此处设置或新建端口」📄，所以这里既能设也能新建。

### 4.3 确认映射关系 ❓

这一步我查不到确切答案，需要你在面板上看一眼。

你要搞清楚的是：你新建的那个对外端口，转发到容器内的哪个端口？

- 如果面板让你自己填容器内端口，填 `25575`，完美。
- 如果面板只给你一个对外端口、固定映射到某个容器端口，那 RCON 可能得改成监听那个端口，
  即把 `rcon.port=` 改成面板指定的容器端口，对外用面板给的端口。

判断方法：新建端口时截个图看看它问你要什么。

### 4.4 在 MCFix 后台填

后台 → 服务器与 Agent → 编辑服务器 → 「RCON」区域：

| 字段 | 填什么 |
|---|---|
| 启用 RCON | 勾上 |
| RCON 地址 | `play.simpfun.cn`（或 `你的后缀.9666.fun`） |
| RCON 端口 | 4.2 里平台给你的对外端口号 |
| RCON 密码 | 和 `server.properties` 里完全一致，注意别带前后空格 |

「执行器」这一项可以保持 `none`，RCON 是叠加在它上面的，不是二选一。

### 4.5 测试（这一步能同时验证第 ③ 关）

最直接的办法是在装 MCFix 的那台机器上跑：

```bash
php bin/mcfix.php diagnose <服务器id> <玩家名> cannot_join
```

输出里会有一条 `[✓] whitelist` / `[✗] whitelist`：

- `[✓]` → 三关全过，RCON 通了
- 连不上 / 超时 → 第 ③ 关没过：那个端口不是裸 TCP 转发，或者防火墙没放行

> 顺便说一句：如果 MC 游戏本身能从外网连上（玩家进得去），
> 那平台至少对游戏端口做了 TCP 转发。新增端口是否同样处理，就是 4.3/4.5 要回答的。

### 4.6 通了之后多了什么

- 诊断：TPS、在线人数、白名单开关、玩家是否在白名单、是否被封禁/禁言
- 修复：加白名单、解封、解禁言、踢人、清背包、保存世界、重载插件
- 而且有回显，执行成功没成功，系统直接看得到。这比面板控制台可靠得多
  （[坑 4](面板服接入指南.md#坑-4面板控制台没有回显已投递不等于执行成功)）

重启类动作建议仍然关掉，见 2.3。

## 五、方案 C：Agent（先确认 PHP，否则免谈）

### 5.1 机制上，简幻欢其实满足条件 🔍

MCFix Agent 的要求是：能在 MC 机器上跑一个常驻的 PHP 进程，且能主动外连。

| 要求 | 简幻欢 | 依据 |
|---|---|---|
| 能跑常驻进程 | ✅ | `start.sh` 是 bash，可以 `php agent.php &` 再 `exec java ...` |
| 能主动外连 | ✅ | 官方没禁止出站；Agent 不需要入站端口 |
| 能放文件 | ✅ | 文件管理 + SFTP |
| 有 PHP | ❓ | 唯一的未知数 |

### 5.2 怎么查有没有 PHP（10 秒）

简幻欢的面板控制台可以变成交互式 shell。官方教的办法（原文是拿它当 tar 用的）：

> 1. 修改启动参数：将 `start.sh` 的主启动参数改为 `bash`，或者在第一行添加 `bash`
> 2. 启动服务器，输入命令即可

所以：

1. 实例 → 文件 → 编辑 `start.sh`，把 java 那行注释掉，加上 `bash`
2. 回到控制台，启动实例
3. 在控制台里敲：

```bash
php -v
```

有版本号输出 → Agent 路线可行。
`php: command not found` → 基础镜像里没有，见 5.4。

顺便可以一次把好几个问题都问清楚：

```bash
php -v                 # PHP 在不在、版本够不够（要 7.4+）
which php curl tar     # 常用工具
cat /etc/os-release    # 什么发行版
echo $SERVER_MEMORY    # 官方文档里提到的内存变量
```

> ⚠️ 查完记得把 `start.sh` 改回去（去掉 `bash`、取消 java 的注释）。
> 官方文档里就这么写的："强制关闭服务器，将 start.sh 中之前提到的 bash 删除或注释"。

### 5.3 如果有 PHP，怎么让它常驻

在 `start.sh` 里，启动 java 之前把 Agent 挂到后台：

```bash
#!/bin/bash

openjdk17="/usr/bin/jdk/jdk-17.0.6/bin/java"
maxmem=$((SERVER_MEMORY - 1000))

# MCFix Agent 常驻（不需要入站端口，主动外连面板）
php /home/container/mcfix-agent.php >> /home/container/mcfix-agent.log 2>&1 &

exec ${openjdk17} -Xms1024M -Xmx${maxmem}M -jar server.jar nogui
```

要点：

- `exec`：让 java 接管容器主进程，别让 Agent 的 `&` 影响实例的生命周期管理
- Agent 和它的 `config.php` 放一起（`agent/mcfix-agent.php` 里写明配置是同目录的 `config.php`）
- 路径用容器内的绝对路径，不是简幻欢文件管理器里看到的路径，用 `pwd` 确认

> 📄 官方提示「当您修改启动参数后，使用差量更新将不再对该文件进行更新，
> 可能导致您需要重新修改启动参数后才可开服」。改 `start.sh` 前先备份一份。

### 5.4 如果没有 PHP

三条路，按推荐度排：

1. 退回方案 B（RCON），性价比最高，能覆盖白名单/解封/保存这条主链路
2. 退回方案 A，只用客户端分析，零维护
3. 自定义镜像。简幻欢支持 `自定义镜像`，理论上可以自带 PHP 环境。
   但这属于"自己维护一套镜像"，官方免责（第三方镜像由开发者负责），
   不在本指南范围内，也建议你先想清楚值不值

## 六、简幻欢特有的坑

### 坑 1：实例被销毁，被误判成"服务端崩了"

连续 7 天不开启 → 实例自动销毁。MCFix 看到的现象和"服务器挂了"一模一样。

对策：看到 `server_offline`，先去简幻欢控制台「记录」页确认实例还在不在。

### 坑 2：自动重启可能把服务器"重启没了"

官方明说晚高峰关了可能起不来。在简幻欢上关掉重启类配方。

### 坑 3：地址别填成容器内地址

`play.simpfun.cn` / `你的后缀.9666.fun` 是从外网用的地址，
MCFix 也是从外网连的，所以填这个是对的。
填 `127.0.0.1` 或容器内网地址会连不上，见
[坑 1](面板服接入指南.md#坑-1把地址填错误判成服务端挂了)。

### 坑 4：SFTP 传完文件必须修权限

官方警告：不走「工具箱 → 解决权限和文件名乱码问题」，会因权限不足导致服务器运行异常。

### 坑 5：千万别删 `start.sh`

官方标红警告。误删要自己在根目录重建，再用工具箱修复。

### 坑 6：改过 `start.sh` 后，差异更新不再更新它

官方原话见 5.3。改之前备份。

### 坑 7：内存预留不够会被强杀，看起来像崩溃

`start.sh` 默认留了 `SERVER_MEMORY - 1000`。预留太少，实例会因内存不足频繁被终止，
日志上表现为服务端莫名消失，很容易被当成崩溃去排查。

## 七、你自己在面板里看一圈（5 分钟）

我没有简幻欢账号，下面这几个问题的答案会直接决定这份文档怎么写。
你顺手看一眼，把结果告诉我（或提 issue），我来把 ❓ 换成结论：

| # | 在哪里看 | 要回答的问题 |
|---|---|---|
| 1 | 实例 → 管理 → 「实例端口」 | 有没有"新建"按钮？有的话新建时让你填什么？ |
| 2 | 实例 → 管理 | 有没有 SFTP 那一栏？地址/端口/用户名长什么样？ |
| 3 | 实例 → 文件 | `server.properties` 能不能直接编辑？ |
| 4 | 控制台（把 `start.sh` 改成 `bash` 后） | `php -v` 有输出吗？`cat /etc/os-release` 是什么？ |
| 5 | 实例页 | 显示给你的连接地址和端口具体是什么格式？ |

第 1 和第 4 题最关键，它们分别决定 RCON 和 Agent 两条路能不能走。
