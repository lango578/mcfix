# 宝塔部署速查（照着敲就行）

> 目标：`https://mc.example.com` 上跑一个反馈站，5 分钟内让玩家能提交反馈、系统能自动验证并修复。
> 文中 `mc.example.com` 换成你自己的域名或服务器 IP，`81` 换成你装的 PHP 版本号。

---

## 第 0 步：确认环境

宝塔【软件商店 → 已安装】检查：

| 项目 | 要求 | 在哪改 |
|---|---|---|
| PHP | 7.4 / 8.0 / 8.1 / 8.2 / 8.3 | 软件商店安装 |
| `pdo_sqlite` `mbstring` `json` | 必须有 | PHP 设置 → 安装扩展 |
| `openssl` | 强烈建议（签名令牌、HTTPS 出网） | 同上 |
| `curl` | 可选，没有会自动退回 stream 方式 | 同上 |
| `sqlite3`（命令行） | 可选，但备份要用它 | `apt install sqlite3` / `yum install sqlite` |
| `proc_open` | 用 agent 模式可选；用 local/ssh 必须放开 | PHP 设置 → 禁用函数 → 删掉它 |

命令行确认一下（宝塔终端）：

```bash
which php                                    # 记下这个路径，计划任务要用
php -m | grep -E 'pdo_sqlite|mbstring|openssl'
php -v
```

## 第 1 步：上传代码

方式 A（推荐，宝塔文件管理器）：

1. 【文件】→ 进入 `/www/wwwroot/`
2. 新建目录 `mcfix`
3. 把项目压缩包上传进去 → 右键【解压】→ 确认结构是 `/www/wwwroot/mcfix/public/index.php`

方式 B（终端）：

```bash
cd /www/wwwroot
mkdir -p mcfix && cd mcfix
# 上传 mcfix.zip 后：
unzip -o mcfix.zip
ls -la    # 应该能看到 public/ src/ agent/ bin/ config.example.php
```

---

## 第 2 步：建站点 + 指向 public

【网站】→【添加站点】：

- 域名：`mc.example.com`
- 根目录：`/www/wwwroot/mcfix`
- PHP 版本：选你装的那个
- 数据库：不创建

建好后 → 点站点名进设置：

1. 【网站目录】→ 运行目录 → 选择 `/public` → 保存 ← 最关键的一步
2. 【SSL】→ Let's Encrypt → 申请 → 开启【强制 HTTPS】
3. 【配置文件】里确认有这一段（宝塔一般默认就有）：

```nginx
location ~ ^/(\.user.ini|\.htaccess|\.git|\.env|\.svn|\.project|LICENSE|NOTICE|README.md) {
    return 404;
}
```

> 为什么必须指向 `public`？因为 `config/config.php` 里存着签名密钥和 Agent 令牌，
> `storage/data/mcfix.sqlite` 里存着所有工单。Nginx 不会读 `.htaccess`，
> 只有把网站根目录收进 `public/` 才能真正挡住它们。

---

## 第 3 步：权限

宝塔【终端】：

```bash
cd /www/wwwroot/mcfix
bash deploy/install.sh
```

这个脚本会自动：建好 `storage/` 下的所有运行时目录、把属主改成 `www`、
把 `storage` 设成 775、找出你装的 PHP 路径，并跑一次环境自检 + doctor。

> 不想跑脚本？手工等价操作：
> ```bash
> cd /www/wwwroot/mcfix
> mkdir -p storage/{data,logs,cache,locks,ratelimit,keys} config
> chown -R www:www storage config
> chmod -R 755 .
> chmod -R 775 storage
> ```

自检：

```bash
sudo -u www test -w /www/wwwroot/mcfix/storage && echo "storage 可写 ✓" || echo "storage 不可写 ✗"
```

如果宝塔开了【防跨站攻击(open_basedir)】，确认允许的路径包含 `/www/wwwroot/mcfix`（默认包含站点根目录，没问题）。

## 第 4 步：安装向导

浏览器打开：

```
https://mc.example.com/?r=install
```

1. 环境自检：全绿 → 下一步
2. 管理员密码：≥ 8 位；站点地址会自动填好，确认是 `https://` 开头 → 保存
   （这一步会同时随机生成后台私有入口路径）
3. 添加第一台 MC 服务器：

| 字段 | 例子 | 说明 |
|---|---|---|
| 显示名 | 生存服 1.20.1 | 玩家看到的名字 |
| 服务器ID | survival | 留空会自动生成 |
| 地址 | mc.example.com | 玩家连接用的地址（也可以填 MC 机器内网 IP） |
| 端口 | 25565 | |
| MC 服务端目录 | /www/minecraft/survival | 放 server.jar 和 logs 的那一层 |
| 日志路径 | logs/latest.log | 相对 MC 目录 |
| RCON 密码 | （填上） | 强烈建议填，很多问题能秒修 |
| 守护方式 | systemd | 决定"重启"怎么执行 |
| systemd 单元名 | minecraft-survival | screen/tmux 就填会话名 |

完成后页面会给你四样东西：

- ✅ 玩家反馈链接（发到群里）
- ✅ 管理后台地址（形如 `https://mc.example.com/?r=console-a1b2c3d4e5f6a7b8`），存进书签
- ✅ Agent 的 `config.php` 内容
- ✅ systemd 部署命令

> 关于后台地址：它和玩家页面是两个独立入口。玩家页面上没有任何指向它的链接，
> 后台自己的登录 cookie 也只作用于这条路径。请把这个地址当密码一样对待，别写进公告或截图里。
> 忘了可以去 `config/config.php` 里搜 `'path' =>` 找回来。

### 建议立刻做的两件事

1. 进后台 → 【系统设置 → 后台入口与访问控制】→ 填 IP 白名单
   （只允许你自己的 IP 访问，即使路径泄露别人也进不来）
2. 顺手把后台路径改成你自己好记的一串（≥ 10 位），改完会用新地址重新登录

## 第 5 步：部署 MC 侧 Agent

在 MC 服务器所在的那台机器上操作（不是宝塔这台）。

```bash
mkdir -p /opt/mcfix
cd /opt/mcfix
```

把项目里的 `agent/mcfix-agent.php` 上传到 `/opt/mcfix/`，然后创建 `config.php`，
内容就是安装向导第 3 步给你的那段（形如）：

```php
<?php
return [
    'panel_url'  => 'https://mc.example.com/index.php?r=api.agent&action=poll',
    'server_id'  => 'survival',
    'token'      => '刚才生成的令牌',
    'mc_dir'     => '/www/minecraft/survival',
    'log_path'   => 'logs/latest.log',
    'listen_port'=> 25565,
    'disk_path'  => '/www/minecraft',
    'guard'      => [
        'type'    => 'systemd',
        'service' => 'minecraft-survival',
        'session' => '',
    ],
    'interval'     => 8,
    'poll_timeout' => 20,
];
```

自检 + 试跑：

```bash
php /opt/mcfix/mcfix-agent.php --check
php /opt/mcfix/mcfix-agent.php --once --verbose
```

`--check` 会逐项打印：PHP 版本、proc_open、mc_dir 是否存在、日志文件、面板连通性、进程、端口、磁盘。
面板连通性必须是"正常 ✓"，否则回去检查 `panel_url` 和 `token`。

常驻运行：

```bash
cat > /etc/systemd/system/mcfix-agent.service <<'EOF'
[Unit]
Description=MC Fix Agent
After=network-online.target

[Service]
Type=simple
ExecStart=/usr/bin/php /opt/mcfix/mcfix-agent.php
Restart=always
RestartSec=5
User=root

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now mcfix-agent
journalctl -u mcfix-agent -f      # 看实时日志，Ctrl+C 退出
```

回到面板后台【服务器与 Agent】，那台服务器的卡片上应该变成 Agent 在线（绿点）。

---

## 第 6 步：面板侧计划任务

宝塔【计划任务】→【添加任务】：

- 任务类型：Shell 脚本
- 任务名称：MCFix 维护
- 执行周期：每分钟
- 脚本内容：

```bash
cd /www/wwwroot/mcfix && /www/server/php/81/bin/php bin/mcfix.php cron
```

再添加一条每日备份（可选）：

- 执行周期：每天 04:00
- 脚本内容：

```bash
# 用 sqlite3 自己的 .backup：数据库开了 WAL，直接 cp 可能拿到不一致的快照
# （内层的单引号要保留，它属于 .backup 命令的参数）
sqlite3 /www/wwwroot/mcfix/storage/data/mcfix.sqlite \
  ".backup '/www/backup/mcfix-$(date +\%F).sqlite'"

find /www/backup -name 'mcfix-*.sqlite' -mtime +30 -delete
```

没有 `sqlite3` 命令时先装：`apt install sqlite3`（Debian/Ubuntu）或 `yum install sqlite`（CentOS）。

---

## 第 7 步：开 RCON（强烈建议）

在 MC 机器上编辑 `server.properties`：

```properties
enable-rcon=true
rcon.port=25575
rcon.password=用 openssl rand -hex 16 生成一串
broadcast-rcon-to-ops=false
```

```bash
# 生成密码
openssl rand -hex 16

# 重启服务端（按你的方式）
systemctl restart minecraft-survival
# 或 screen -S mc-survival -X stuff "stop\n" 等它自己重启

# 确认端口起来了
ss -lntp | grep 25575
```

把这串密码填到后台【服务器与 Agent → 对应服务器 → 配置 → RCON 密码】，勾选"启用 RCON"，保存。

> **只放行面板 IP**（MC 机器上执行，`面板IP` 换成你宝塔服务器的公网 IP）：
> ```bash
> iptables -I INPUT -p tcp --dport 25575 -s 面板IP -j ACCEPT
> iptables -A INPUT -p tcp --dport 25575 -j DROP
> ```

## 第 8 步：验收

在宝塔终端：

```bash
cd /www/wwwroot/mcfix

# 1. 总体自检
/www/server/php/81/bin/php bin/mcfix.php doctor

# 2. 看服务器与 Agent 状态
/www/server/php/81/bin/php bin/mcfix.php servers

# 3. 直接诊断一次（不建工单）
/www/server/php/81/bin/php bin/mcfix.php diagnose survival Steve cannot_join

# 4. 模拟玩家提交，跑完整闭环
/www/server/php/81/bin/php bin/mcfix.php test-feedback survival Steve "进不去服了，提示不在白名单"
```

第 4 步会打印：工单号 → 验证结论 → 每项检查的真实结果 → 修复动作 → 复验结果。
这一步全绿，就说明整条链路都通了。

把后台【接入与排查】页里的玩家反馈链接发到群里，让玩家用手机点开试试。

## 附：不同服务器形态怎么配

系统有 6 条执行通道，都配在一台服务器的配置里，可以叠加使用。诊断和修复会按能力自动选路：

| 通道 | 能做什么 | 需要什么 |
|---|---|---|
| RCON | 发游戏指令（白名单、解封、踢人、保存世界、重载） | 服务端开 `enable-rcon` |
| 面板 API | 读日志、发指令、开关机、列目录、读文件 | 面板的 API 密钥（见下） |
| Agent | 全部：进程、端口、磁盘、CPU、日志、MOD 清单、重启 | MC 机器上跑一个小程序 |
| SSH | 同 Agent，但面板要能 SSH 到 MC 机器 | 密钥或密码 |
| local | MC 与面板同机时直接执行 | `proc_open` 未被禁用 |
| none | 只做面板直连探测（MC 协议 + RCON） | — |

### 选路规则（知道这个就不会配错）

```
诊断读日志   → 面板 API（能读就行，不用装东西）→ Agent → 跳过并说明原因
游戏指令     → RCON（有回显，最可靠）→ 面板控制台
进程开关机   → RCON stop + 守护重启 → 面板 power → Agent
进程/端口/磁盘 → Agent / SSH / local（面板 API 拿不到这些）
```

### 场景 A：MCSManager 面板服

后台【服务器与 Agent → 配置 → 面板 API】：

| 字段 | 填什么 | 从哪找 |
|---|---|---|
| 面板类型 | MCSManager | |
| 面板地址 | `http://127.0.0.1:23333` | 你打开面板的地址 |
| API 密钥 | 32 位串 | 面板【设置 → API 接口】生成 |
| 远程服务 UUID | `xxxxxxxx-xxxx-...` | 面板【远程服务】列表里那条记录的 UUID |
| 实例 UUID | `xxxxxxxx-xxxx-...` | 进实例后地址栏 / 实例设置里 |
| 面板内的服务端目录 | `/home/container` 之类 | 面板文件管理里的实例根目录 |

填完点【测试面板 API】。通了之后不用装 Agent 就能：读日志做诊断、发白名单/解封指令、重启实例。
想要进程/磁盘/MOD 清单那些细节，再叠加 Agent。

> 如果测试失败说接口 404，多半是这个版本路径不同：
> 在配置的 `endpoints` 里覆盖，例如把下载接口改成
> `{"download":"/api/files/download","outputlog":"/api/protected_instance/outputlog"}`。

### 场景 B：翼龙 / Pterodactyl（含 Pelican）

| 字段 | 填什么 |
|---|---|
| 面板类型 | 翼龙 / Pterodactyl |
| 面板地址 | `https://panel.example.com` |
| API 密钥 | `ptlc_...`（推荐，服务器子用户密钥）或 `ptla_...`（管理员密钥） |
| 密钥模式 | client / application |
| 服务器短 ID | 面板地址栏 `/server/xxxxxxxx` 里的那 8 位 |
| 面板内的服务端目录 | `/home/container` |

优先用 client 模式：权限范围小，泄露风险低。它一样能发指令、开关机、读日志。
只有需要看资源占用（`resources` 接口）时才用 application。

### 场景 C：宝塔上直接跑 MC（面板和 MC 同机）

这种最省事，两条路配合：

1. 宝塔 API（读日志/列目录/进程开关机）
   【面板 API】类型选「宝塔面板」，填面板地址、`API 密钥`（宝塔【设置 → API 接口】生成）、
   `进程 ID`（进程守护管理器里那个 MC 项目的 ID，列表里能看到）
2. RCON（发游戏指令）
   `server.properties` 里开 `enable-rcon`，把密码填到 RCON 那一栏

宝塔接口的签名规则比较特殊（`request_token` + `request_sign`），代码里已经实现；
如果宝塔版本不同导致签名不通过，错误信息会直接显示在【测试面板 API】的结果里。

### 场景 D：租用服 / 只有 Web 控制台

简幻欢、雨云、各种自研面板，通常没有标准 API，但可能有能发指令的 HTTP 接口。

情况 1：有 HTTP 接口 → 【面板 API】类型选「自定义 HTTP 接口」，填：

```
指令接口 URL   http://127.0.0.1:8080/api/console
请求体模板     {"cmd":"{command}"}          ← {command} 会被替换成 game 指令
回显字段路径   data.output
日志接口 URL   http://127.0.0.1:8080/api/log?tail=2000   ← 诊断必需，有它就能自动分析日志
开关机 URL     http://127.0.0.1:8080/api/power
开关机请求体   {"action":"{action}"}        ← {action} = start|stop|restart|kill
```

情况 2：完全没有接口 → 只能：
- 开 RCON（大多数租用服允许改 `server.properties`），拿到"发指令 + 查白名单"的能力
- 或者让服务商在机器上跑 Agent（少数服务商支持）
- 都没有的话，系统仍然能给出完整的客户端日志分析，只是服务端修复要人工做

### 场景 E：自己管理的机器 / 独立主机

配 Agent 拿到全部能力，见上面第 5 步。这是功能最全的形态。

> 可以叠加：同一台服务器同时配「面板 API + RCON + Agent」是最佳实践，
> 面板负责读日志（快），RCON 负责发指令（有回显），Agent 负责进程与重启（最可控）。

## 附：Nginx 站点配置参考

如果不用宝塔的默认模板，或者想加安全响应头，可以把站点配置写成：

```nginx
server {
    listen 443 ssl http2;
    server_name mc.example.com;
    root /www/wwwroot/mcfix/public;   # 关键：指向 public
    index index.php;

    ssl_certificate     /www/server/panel/vhost/cert/mc.example.com/fullchain.pem;
    ssl_certificate_key /www/server/panel/vhost/cert/mc.example.com/privkey.pem;

    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options SAMEORIGIN always;
    add_header Referrer-Policy strict-origin-when-cross-origin always;

    # 挡住误传出来的敏感文件
    location ~ ^/(config|storage|src|bin|views|admin|deploy)/ {
        deny all;
        return 404;
    }
    location ~ /\.(?!well-known) {
        deny all;
        return 404;
    }

    # 静态资源长缓存
    location ~* \.(css|js|png|jpg|svg|ico|woff2?)$ {
        expires 7d;
        access_log off;
    }

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/tmp/php-cgi-81.sock;
        fastcgi_index index.php;
        include fastcgi.conf;
        fastcgi_read_timeout 120;   # 诊断/等待服务端恢复可能超过默认 60s
    }
}
```

`fastcgi_read_timeout` 建议放宽到 120 秒：重启服务端后系统要等端口恢复，
默认 60 秒可能刚好卡在边界上。

## 附：升级流程

```bash
# 1. 备份（数据库用 .backup，不要 cp —— WAL 模式下热拷贝可能不一致）
sqlite3 /www/wwwroot/mcfix/storage/data/mcfix.sqlite \
  ".backup '$HOME/mcfix-backup-$(date +%F).sqlite'"
cp /www/wwwroot/mcfix/config/config.php ~/mcfix-config-$(date +%F).php
tar czf ~/mcfix-code-$(date +%F).tar.gz -C /www/wwwroot mcfix     # 代码整体也备一份

# 2. 覆盖代码（保留 config/ 和 storage/）
cd /www/wwwroot/mcfix
unzip -o ~/mcfix-new.zip -x 'config/*' 'storage/*'

# 3. 修权限 + 自检
chown -R www:www . && chmod -R 775 storage
/www/server/php/81/bin/php bin/mcfix.php doctor

# 4. MC 机器上同步更新 Agent（如果有改动）
systemctl restart mcfix-agent
```

数据表结构是幂等创建的，覆盖代码后第一次访问会自动完成迁移，不需要手工执行 SQL。
