# BisectHosting 面板服接入指南

给用 BisectHosting 的服主看的。通用面板接入原理见 [面板服接入指南](面板服接入指南.md)，这份只讲 BisectHosting 的具体做法。

---

## ⚠️ 第一步：先确认你的面板是哪一种（别跳过）

BisectHosting 不止一种面板。查证时两边资料对不上：

| 来源 | 说的是 |
|---|---|
| 第三方集成文档 | 他们的 Starbase 面板基于 Pterodactyl |
| 一个开源 Multicraft 客户端库 | BisectHosting 被列为 Multicraft 主机，API 端点是 `https://games.bisecthosting.com/api.php` |

两份可能都对，他们很可能两种面板并存（不同产品线、或不同时期开的服务器）。别照着猜，先花 30 秒确认：

| 看什么 | Pterodactyl 系 → 走第 2 节的路线 A | Multicraft → 见下方说明 |
|---|---|---|
| 地址栏 | `.../server/<一段短ID>` | 带 `index.php?page=server` 之类 |
| 界面 | 深色、左侧栏（Console / Files / Databases / Backups） | 蓝色调、顶部导航、左侧是服务器列表 |
| 有没有 Multicraft 字样 | 没有 | 页脚或标题上常写着 |
| 打开 `/account/api` | 能打开 | 打不开 |
| 打开 `/api.php` | 404 | 有 API 响应 |

> 最省事的判断：浏览器打开 `https://<你的面板域名>/api.php`。
> 返回 Multicraft 的 API 响应就是 Multicraft；404 就是 Pterodactyl 系。

如果你确认是 Multicraft：1.11.0 起 MCFix 已经有 Multicraft 适配器了，所以两条路都能走。

1. 面板 API（推荐，能力最全）。后台类型选 `Multicraft`，填面板地址（要带 `/api.php`）、用户名、API 密钥、数字服务器 ID。详见[主机商接入索引](主机商接入索引.md#-multicraft-适配器已实现1110)。
2. RCON。见下面第 3 节。面板 API 抽风时它还能兜底。

> Multicraft 的 API 没有文件接口，所以"读 mods 目录 / 取回模组"用不了，但下发指令、开关机、读日志、看资源都是完整的，自动重启也能用。

下面第 2 节（路线 A）只适用于 Pterodactyl 系。确认是 Multicraft 的话，直接跳到第 3 节配 RCON。

---

## 0. 先看结论，再动手

BisectHosting 能走两条路，建议两条都配：

| | 路线 A：面板 API | 路线 B：RCON |
|---|---|---|
| 能力 | 开关机、发指令、读日志、读文件、看资源占用 | 只能发游戏指令 |
| 自动重启 | ✅ 能 | ❌ 不能 |
| 能不能读到服务端日志 | ✅ 能 | ❌ 不能 |
| 配置难度 | 中等（要建 API 密钥） | 简单 |
| 一定能用吗 | 要先确认面板有没有开放 API | 面板支持 RCON 就能用 |

三个必须知道的前提：

1. `executor` 必须设成 `none`（不是 `agent`）。原因见下一节，设错了整个修复功能会静默失效。
2. Agent 路线用不了。BisectHosting 不给 SSH，也不允许你跑常驻进程，所以没法在 MC 机器上挂 Agent。
3. 配好面板 API 之后，自动重启是可用的。MCFix 会先 `save-all flush`，再调面板重启，最后等端口恢复才判定成功。

---

## 1. 最容易踩的坑：`executor` 一定要填 `none`

这是整份教程里最容易错、而且错了不会报错的一步。

MCFix 有六条执行通道。后台的执行器下拉框决定"这台服务器用哪条"。界面上是这四个选项：

| 界面选项 | 真正含义 | BisectHosting 上 |
|---|---|---|
| `agent（MC 侧小程序，推荐）` | 把任务排队，等 MC 机器上的 Agent 来领 | ❌ 永远领不走：任务会一直卡在队列里 |
| `ssh（面板 SSH 到 MC 机器）` | 走 SSH 执行 | ❌ 没有 SSH |
| `local（同一台机器）` | 面板和 MC 在同一台机器上，直接本地执行 | ❌ 不适用 |
| `none（面板服选这个：用面板 API 修）` | 没有 Agent/SSH，把面板 API 的能力用满 | ✅ 选这个 |

为什么 `agent` 不会报错：它会把任务写进队列、状态显示"排队中"，然后一直等一个永远不会上线的 Agent。界面上看起来一切正常，玩家那边只会觉得"说修了但没反应"。

为什么 `none` 这个名字容易误导：它在界面上原本写的是「none（只诊断）」，听起来像"不修"。实际上配好面板 API 之后，`none` 会走 `panelFallback`，用面板的开关机接口重启、用面板控制台发指令、用面板文件接口读日志。面板服就该选它（这一项在 v1.10.1 已把文案改成"面板服选这个：用面板 API 修"）。

## 2. 路线 A：面板 API（推荐）

### 2.1 先确认你的面板是不是 Pterodactyl 系

BisectHosting 的 Starbase 面板是基于 Pterodactyl 构建的，所以 MCFix 里现成的「翼龙 / Pterodactyl」适配器可以直接用。

> ⚠️ 这一点没能亲自验证。BisectHosting 的站点挡住了抓取，这个结论来自第三方集成文档（[DeployHQ 的 BisectHosting 指南](https://www.deployhq.com/guides/bisecthosting)，里面写明 "Their Starbase panel (built on Pterodactyl)"）。
> 请你自己确认一下：登录面板，看浏览器地址栏是不是 `https://<你的面板域名>/server/<一串短ID>` 这种形状。是的话就是 Pterodactyl 系。

### 2.2 拿到服务器短 ID

看地址栏：

```
https://panel.xxxxxxxx.bisecthosting.com/server/3f2a1b9c
                                            ^^^^^^^^ 这一段
```

`3f2a1b9c` 就是 `server_id`，一会儿要填进 MCFix。

### 2.3 建一个 API 密钥

Pterodactyl 系面板的 API 密钥页面通常在 `/account/api`。完整地址：

```
https://<你的面板域名>/account/api
```

在那一页点 Create API Key：

- Description：随便写，例如 `mcfix`
- Permissions：见下面的建议

MCFix 需要这些能力，所以密钥至少要包含：

| 权限 | 用来做什么 |
|---|---|
| `websocket.connect` | 读控制台输出（日志） |
| `control.console` | 发送指令（加白名单、解封、踢人…） |
| `control.start` / `control.stop` / `control.restart` | 开关机与自动重启 |
| `file.read` | 读日志文件、读 mods 目录 |
| `allocation.read`（或 `websocket.connect`） | 看资源占用 |

图省事的话，直接全勾。这是你自己服务器的密钥，泄露范围只限这一台服务器。

创建后会显示一串以 `ptlc_` 开头的密钥，它只显示一次，立刻复制下来。

> `ptlc_` 和 `ptla_` 的区别：`ptlc_` 是客户端密钥，只能操作你自己的服务器；`ptla_` 是面板管理员密钥，能操作整个面板。BisectHosting 不会给你 `ptla_`，你也不该要。用 `ptlc_` 就够，而且更安全。

### 2.4 在 MCFix 后台填写

后台 → 服务器与 Agent → 编辑你的服务器 → 面板 API 区域：

| 界面字段 | 选/填 | 说明 |
|---|---|---|
| 类型 | `翼龙 / Pterodactyl（含 Pelican）` | 列表里就这一项最接近 |
| 密钥模式（翼龙） | `client（ptlc_，权限小）` | 别选 `application`，BisectHosting 不会给你 `ptla_` |
| 面板地址 | `https://<你的面板域名>` | 结尾不带斜杠，也不要带 `/server/xxx` |
| API 密钥 | 刚才复制的 `ptlc_...` | 注意别多复制了空格 |
| 服务器短 ID（翼龙） | 2.2 拿到的短 ID，如 `3f2a1b9c` | |
| 面板内的服务端目录 | `/home/container` | 占位提示里写的就是这个，不用改 |
| 超时 | `10` 秒 | |

同时确认这两个地方：

- 执行器 选 `none（面板服选这个：用面板 API 修）`
  > 界面上这一项以前写的是"只诊断"，容易让人以为它不能修，但面板服就该选它。选了它，MCFix 会把面板 API 的能力用满（开关机、发指令、读日志）。更详细的解释见第 1 节。
- 启用面板 API 勾上

保存。

### 2.5 自检

保存后，在同一页点「测试面板 API」。成功的话会显示：

```
翼龙面板连接成功：<你的服务器名>（当前状态 running），支持：console、power、read_log、stat_log、read_file、list_dir、resources
```

看到 `power` 就说明自动重启可用。

如果失败，错误信息会带上面板的原话，对照第 6 节的排查表。

## 3. 路线 B：RCON（保底）

如果面板没开放 API（或者你不想建密钥），RCON 是保底方案。它只能发游戏内指令，但覆盖了最常见的几类问题。

### 3.1 在面板里开启 RCON

BisectHosting 的面板一般可以在 配置文件 / server.properties 里直接改（有些面板把 RCON 做成单独的开关页面）。需要改这三行：

```properties
enable-rcon=true
rcon.port=25575
rcon.password=换成一串你自己的随机密码
```

注意事项：

- 端口别用 25565，那是游戏端口。`25575` 是惯例值，被占用的话随便换一个 1024–65535 之间没被占用的
- 密码别用简单值。RCON 等于服务器控制台，密码泄露就等于别人能以管理员身份执行任何指令。建议 20 位以上随机串
- 改完重启服务器才生效

### 3.2 验证 RCON 通了

重启后，在面板的控制台里敲：

```
list
```

如果能看到玩家列表，说明服务器在正常跑。RCON 本身是否开通，看面板有没有"RCON 已连接"之类的状态提示，或者直接让 MCFix 测（下一步）。

### 3.3 在 MCFix 后台填写

后台 → 服务器与 Agent → 编辑服务器 → RCON 区域：

| 界面字段 | 填什么 |
|---|---|
| 启用 RCON | 勾上 |
| 地址 | 你服务器对外的连接地址（和玩家填在客户端里的一样） |
| 端口 | 你刚才设的 RCON 端口（默认 `25575`） |
| 密码 | 你刚才设的 RCON 密码 |
| 超时 | `3` 秒 |

> 地址填什么？填玩家进服用的那个地址（例如 `play.example.com` 或 BisectHosting 给你的 IP）。
> MCFix 是从你自己的面板站去连这个地址的，所以必须是公网可达的。填 `127.0.0.1` 一定连不上。

> ⚠️ 界面上没有单独的"测试 RCON"按钮。想验证 RCON 通不通，用这条命令（在你面板站的终端里跑）：
>
> ```bash
> php -r '$f=fsockopen("tcp://<服务器地址>",<RCON端口>,$e,$s,5); echo $f?"端口通\n":"连不上：$s\n";'
> ```
>
> 或者更直接：随便让一个玩家提交一次反馈，看后台的操作日志里有没有 RCON 相关的失败记录。

### 3.4 RCON 能修什么、不能修什么

能修：

| 问题 | 动作 |
|---|---|
| 玩家不在白名单 | `whitelist add <玩家>` |
| 玩家被封禁 | `pardon <玩家>` |
| 玩家被禁言 | `unmute <玩家>` |
| 玩家卡在加载界面 | `kick <玩家> <原因>` |
| 卡顿、区块没落盘 | `save-all flush` |
| 改过配置要生效 | `reload confirm` |

不能修：

| 问题 | 为什么 |
|---|---|
| 服务器整个挂了 | RCON 本身连不上，没法让它重启。这是 RCON 方案最大的短板 |
| 读服务端日志 | RCON 不给文件访问 |
| 看磁盘/进程/CPU | 同上 |
| 取回 MOD 文件 | 需要读 mods 目录 |

如果你两条路都配了，MCFix 会优先走 RCON（有回显、最快），RCON 失败再落到面板 API。

## 4. 走哪条路？对照着选

| 你想要的效果 | 只配 RCON | 只配面板 API | 两个都配 |
|---|---|---|---|
| 加白名单 / 解封 / 踢人 | ✅ | ✅ | ✅ |
| 保存世界 / 重载插件 | ✅ | ✅ | ✅ |
| 服务器挂了自动重启 | ❌ | ✅ | ✅ |
| 读服务端日志辅助诊断 | ❌ | ✅ | ✅ |
| 看 TPS、在线人数 | ✅ | ✅ | ✅ |
| 取回 MOD 文件给玩家下载 | ❌ | ✅ | ✅ |
| 面板 API 挂了时还能修 | ✅ | ❌ | ✅ |

结论：能建 API 密钥就两个都配。只配 RCON 的话，"服务器挂了"这个最需要自动化的场景恰好修不了。

## 5. 玩家的崩溃日志：不需要任何服务器权限

这一点单独说，因为它经常被误解。

玩家在反馈页上传的崩溃报告（crash-report / latest.log）走的是网站，不碰你的服务器。

MCFix 会在面板站上解析这份日志（37 条问题规则 + 51 条特征正则），然后：

- 判断是客户端问题还是服务端问题
- 如果是客户端问题（模组冲突、Java 版本、内存不足…），直接告诉玩家怎么修。这一步完全不需要服务器权限，只配 RCON 甚至什么都不配都能用
- 如果是服务端问题，才需要走第 2/3 节的通道去修

所以即使面板 API 不可用，你依然能得到"客户端报错自动诊断"这个核心价值。

## 6. 排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 测试面板连接：`401` | 密钥错了，或用的是 `ptla_` 但没权限 | 重新复制 `ptlc_` 密钥；确认没多复制空格 |
| 测试面板连接：`404` | 面板地址或服务器 ID 错了 | 地址只要域名，不要带 `/server/xxx`；服务器 ID 就是地址栏里那一段 |
| 测试面板连接：`连接超时` | 面板站出不了网，或面板域名写错 | 在面板站的终端里 `curl -I https://<面板域名>` 试试 |
| 测试 RCON：`Connection refused` | RCON 没开，或端口不对 | 回 3.1 检查 `enable-rcon=true` 并重启过服务器 |
| 测试 RCON：`Authentication failed` | 密码不对 | `server.properties` 里的 `rcon.password` 和 MCFix 里填的必须一模一样（注意首尾空格） |
| 测试 RCON：`连接超时` | 地址填成了 `127.0.0.1` 或内网地址 | 改成玩家进服用的公网地址 |
| 任务一直显示"排队中" | `executor` 填成了 `agent` | 改成 `none`，见第 1 节 |
| 修复动作报"该服务器既没配 Agent/SSH，也没有可用 RCON 或面板 API" | 两条路都没配通 | 至少配通一条 |

## 7. 没验证过的部分

不让你踩坑时以为是自己的问题，把没验证的东西列清楚：

1. BisectHosting 的站点挡住了抓取，无法直接登录或查阅他们的面板文档。本文关于"Starbase 面板基于 Pterodactyl"的说法来自[第三方集成文档](https://www.deployhq.com/guides/bisecthosting)，不是亲自确认的。
2. `/account/api` 这个 API 密钥页面是否开放，需要你自己打开看一眼。有些主机商会把这个页面关掉。如果打不开，就走 RCON 路线。
3. RCON 在 BisectHosting 面板里的具体开关位置，各时期的面板版本可能不一样（有的在 `server.properties` 里直接改，有的有单独的 RCON 页面）。本文给的是 Pterodactyl 系的通用做法。
4. 权限勾选项的准确名称可能随 Pterodactyl 版本变化。如果 `control.restart` 之类找不到，先全勾，能用了再收紧。

## 附：这套配置下 MCFix 的工作流

```

玩家点反馈链接 → 提交问题（可附崩溃日志）
        │
        ├─ 日志解析（在面板站上做，不碰服务器）
        │   └─ 判断：客户端问题 → 直接给玩家解决方案，结束
        │
        └─ 服务端问题 → 诊断（面板 API 读日志/资源 + RCON 查 TPS/白名单）
                │
                ├─ 命中规则 → 执行修复
                │   ├─ 面板侧动作（加白名单等）→ 优先 RCON，失败落面板控制台
                │   └─ 重启类 → 面板 power 接口（先 save-all，重启后等端口恢复）
                │
                ├─ 复验 → 确认修好了
                └─ 通知玩家（邮件 / 你的通知渠道）
```

注意：重启类动作默认需要管理员在后台点"批准"（后台 → 系统设置 → 自动化与风控 → `重启类动作需要管理员批准`）。想让它全自动，把这个开关关掉，但请先确认你已经理解风险。
